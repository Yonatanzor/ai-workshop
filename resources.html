Everything students and educators need to run the course or work through it independently.

The Five Questions

Ask these of every tool, in every session, until they are a habit.

01
What was it trained on, or given to read?
Identify the data the model has access to — and what it doesn't.
02
How would I know if this is wrong?
Every output needs a verification strategy before it is used.
03
Who or what is missing from its data?
Gaps in training data become gaps in outputs — sometimes invisible ones.
04
What did using it cost — privacy, time, or a skill I did not practise?
Every tool use has a cost beyond the subscription fee.
05
Would a non-AI method do this better?
AI is not always the right tool. The four-test card sort applies here too.

Data Confidentiality Tiers

Course rule
No identifiable patient data and no unpublished lab data in any public AI tool. Check, for each tool, whether you are signed in with a personal or an institutional account.
Tier 1
Published papers & public datasets
AI: Any approved tool.
Human: Spot-check output and sources.
Tier 2
De-identified research data
AI: Structure only; code runs where data lives.
Human: Verify results a second way.
Tier 3
Identifiable patient or unpublished lab data
AI: Nothing in public tools.
Human: Approve every input and output.
Tier 4
Anything affecting a patient decision
AI: Drafts only, never actions.
Human: A qualified clinician decides.

Glossary

46 AI terms from across all nine sessions.

Term Definition
A
AgentA model running in a loop — goal → choose a tool → act → read the result → repeat → stop. The model decides the next step; a human or supervisor can approve or block it.
AI disclosureA statement on a finished work explaining what AI did and did not do. Required on the capstone deck and practised in Session 7's governance audit.
AI LifecycleThe end-to-end process of an AI system: data collection → annotation → model training → validation → deployment → monitoring. Human-in-the-loop touchpoints exist at every stage.
API (Application Programming Interface)A defined way for software to communicate. In this course, students call LLM APIs to send prompts and receive completions programmatically.
Attention / TransformerA transformer breaks text into tokens and uses 'attention' — a weighted sum over all previous tokens — to decide which context matters most. The architecture underlying every tool in this course.
B
Bias (model)Systematic error in a model's outputs reflecting skews in its training data, potentially producing unfair or inaccurate results for underrepresented groups.
C
Capstone showcaseThe final session: each group presents one adopted AI workflow (problem, live demo, verification, one failure) in 6 minutes, followed by peer questions.
ChunkA fixed-size passage cut from a document for use in a RAG pipeline. The retrieval step finds the most relevant chunks and passes them to the model as context.
Custom assistantA chat model configured with a specific system prompt, knowledge base, and rules for a defined purpose. The underlying model weights are unchanged.
D
Data leakageA model's training or validation data inadvertently includes information from the test set, making measured performance look better than it really is on unseen data.
Data tierThe course's four-level classification of data sensitivity: Tier 1 (public), Tier 2 (de-identified), Tier 3 (identifiable patient or unpublished), Tier 4 (affects a patient decision).
Deep learningA subfield of machine learning using neural networks with many layers. Most modern AI tools — language models, image classifiers, structure predictors — are deep learning systems.
E
EmbeddingA numerical vector representing text in high-dimensional space. Similar texts have nearby embeddings. Used in RAG pipelines to find relevant chunks by semantic similarity.
Evidence-grounded AIAn AI tool designed to answer only from a defined, trusted set of sources (e.g. peer-reviewed journals) rather than the open web.
F
Failure logA personal record kept by each student across all nine sessions: one AI failure per session — the tool, what was asked, what went wrong, how it was caught.
Fine-tuningContinuing to train a pre-trained model on a smaller, task-specific dataset. Fine-tuning changes the model's weights; prompting does not.
Foundation modelA large model trained on broad data at scale that can be adapted to many downstream tasks. GPT-4, Gemini, and Llama are examples.
Function calling / Tool useA model capability allowing it to request a named function with specific arguments, receive the result, and continue. The backbone of agents in Session 6.
G
GammaAn AI-assisted presentation tool used in Sessions 3 and 7 to rapidly turn outlines or document summaries into slide decks.
Governance auditA structured review of an AI-built tool covering: who can see it, what it invented without being asked, what data it exports, and who would be accountable if something went wrong.
GroundingThe degree to which a model's answer is tied to verifiable external sources rather than generated purely from training.
H
HallucinationWhen an AI model states something confidently that is false or unsupported — not a deliberate lie, but a statistically plausible-sounding output that happens to be wrong.
Human-in-the-loop (HITL)A design pattern requiring a person to review and approve AI outputs or actions before they take effect. Applied in Session 6's supervisor mode.
K
Knowledge baseA set of documents uploaded to a custom assistant or RAG pipeline that the model may draw on when answering.
L
Language model (LLM)A model trained to predict the next token given a sequence of previous tokens. Large language models learn from vast text corpora and can generate, summarise, and reason over text.
M
Machine learningA branch of AI in which systems learn patterns from data rather than being explicitly programmed with rules. Deep learning is a subset.
MAX_STEPSA hard limit on how many tool-call rounds an agent may take before it must stop. Prevents runaway loops. Set to 10 in Session 6.
MCP (Model Context Protocol)A standard that lets an AI model connect to and query external tools or databases directly, rather than relying only on its training.
Model cardA short document published alongside an AI model describing its training data, evaluation, known limitations, and appropriate use cases.
Model MonitoringOngoing tracking of an AI model's performance after deployment to detect drift, failures, or unexpected outputs in real-world use.
N
NotebookLMGoogle's document Q&A and synthesis tool. Users upload sources; answers are grounded in and cited to those sources. Used in Sessions 3 and 5.
P
PerplexityA retrieval-grounded AI search tool that answers questions by first searching the web and generating a cited response. Used in Session 0.
PromptThe input sent to a language model — a system prompt (instructions) plus the user's message. The model generates a completion given the full prompt as context.
Prompt injectionAn attack that embeds new, conflicting instructions inside the input an AI model processes, attempting to override its original system prompt.
Q
QED ScienceAn AI tool that critically reviews scientific reasoning in a document, flagging logical gaps and unsupported claims. Used in Session 0.
R
RAG (Retrieval-Augmented Generation)A technique where relevant documents are retrieved and inserted into the model's context before it generates an answer. Reduces hallucination and allows grounded citation.
Retrieval-groundedA tool that looks something up in real documents before answering, rather than generating purely from training memory.
S
Semantic searchFinding documents by meaning rather than keyword overlap. Requires embedding both the query and documents, then finding the nearest neighbours in vector space.
Supervisor (agent)A human who is asked to approve or refuse each 'act' step before it executes. Demonstrates human-in-the-loop control in Session 6.
System promptInstructions given to a model before the user ever interacts with it, defining purpose, tone, scope, and behavioral rules. Does not change the model's weights.
T
TF-IDFTerm Frequency–Inverse Document Frequency — a classic retrieval method that ranks documents by keyword match, weighted by term rarity. The retrieval step in Session 5's pipeline.
TokenThe smallest unit of text a language model processes — roughly a word or sub-word. Models have a maximum context length measured in tokens.
Tool (agent)A Python function the agent can call by name. Session 6's tools include search_trials, get_trial, check_age, search_pubmed, and send_email.
V
Verification planHow you will confirm that an AI workflow's output is correct before relying on it. Required component of the capstone project scope in Session 8.
Vibe codingBuilding software by describing desired behaviour in natural language and iterating on AI-generated code, rather than writing every line manually. Covered in Session 7.
W
Weights (model weights)The numerical parameters learned during training that define what a model knows and how it behaves. Prompting does not change weights; fine-tuning does.
